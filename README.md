# نوا (Nava)

یک شبکه‌ی اجتماعی کوچک شبیه توییتر، با بک‌اند پایتون (Flask) و پایگاه‌داده‌ی SQLite.
پست متنی، عکس، ویدیو و صدا؛ لایک، بازنشر، پاسخ، دنبال‌کردن، و پیام خصوصی.

## اجرای محلی (روی سیستم خودت)

نیاز داری: **Python نسخه‌ی ۳.۹ به بالا**.

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

حالا آدرس `http://localhost:5000` را در مرورگر باز کن. اولین بار که اجرا می‌شود،
یک پایگاه‌داده‌ی تازه (`backend/nava.db`) با چند پست و کاربر نمایشی می‌سازد.

می‌توانی به‌جای دستورهای بالا، فایل `run.sh` (مک/لینوکس) یا `run.bat` (ویندوز) را
اجرا کنی؛ همین کارها را خودکار انجام می‌دهند.

## کاربران نمایشی

پنج حساب (`sara`, `arash`, `negar`, `kaveh`, `mahsa`) از قبل با چند پست ساخته شده‌اند
تا فید خالی نباشد. این حساب‌ها **ربات نمایشی**اند؛ رمز عبورشان تصادفی و نامعلوم است و
نمی‌شود با آن‌ها وارد شد. اگر برایشان پیام خصوصی بفرستی، بعد از حدود دو ثانیه یک
پاسخ از پیش‌نوشته برمی‌گردانند تا حس گفت‌وگو را نشان دهند — نه پاسخ هوشمند واقعی.

برای استفاده‌ی واقعی، از صفحه‌ی اول «ثبت‌نام» بزن و یک حساب واقعی بساز.

## بازنشانی اطلاعات

برای پاک کردن همه‌چیز و شروع از صفر، سرور را متوقف کن و این را اجرا کن:

```bash
python scripts/reset_db.py
```

این کار پایگاه‌داده را حذف می‌کند (دفعه‌ی بعد که سرور بالا بیاید، دوباره ساخته و
با کاربران نمایشی پر می‌شود) و فایل‌های آپلودی کاربران را پاک می‌کند، اما دو فایل
نمونه‌ی داخلی (`seed_arch.jpg`, `seed_tar.wav`) را نگه می‌دارد.

## دیپلوی روی هاست رایگان

### Render (پیشنهاد اول، خارج از ایران)
۱. یک مخزن گیت از این پوشه بساز و در Render یک «Web Service» جدید از آن بساز.
۲. **Build Command:** `pip install -r backend/requirements.txt`
۳. **Start Command:** `cd backend && gunicorn -w 2 -b 0.0.0.0:$PORT app:app`
   (پیش از این، `gunicorn` را به `backend/requirements.txt` اضافه کن یا با
   `pip install gunicorn` نصبش کن — روی ویندوز از `waitress` استفاده کن.)
۴. در بخش Environment، یک متغیر `SECRET_KEY` با یک رشته‌ی تصادفی و طولانی بساز.
۵. **مهم:** پلن رایگان Render دیسک را بین دیپلوی‌ها پاک می‌کند. برای این‌که
   پایگاه‌داده و فایل‌های آپلودی کاربران از بین نرود، از بخش «Disks» یک
   Persistent Disk بساز و آن را روی مسیر `backend` سوار (mount) کن، یا مسیر
   `DB_PATH`/`UPLOAD_DIR` را در `app.py` به مسیر دیسک دائمی تغییر بده.

### لیارا (داخل ایران)
لیارا هم میزبانی رایگان برای اپ‌های پایتون (Flask/Django) دارد و دامنه‌ی رایگان
می‌دهد. مراحل را از مستندات خودش («دیپلوی Flask») دنبال کن؛ نکته‌ی دیسک دائمی
بالا برای لیارا هم صادق است — بدون آن، هر بار که دوباره دیپلوی کنی داده‌ها پاک
می‌شوند.

هر دو گزینه در طول زمان تغییر می‌کنند؛ قبل از دیپلوی نهایی حتماً صفحه‌ی قیمت‌گذاری
و محدودیت‌های فعلی‌شان را چک کن.

## محدودیت‌های این نسخه (صادقانه بگویم)

- **سرور توسعه:** دستور `python app.py` از سرور توسعه‌ی Flask استفاده می‌کند که
  برای کاربر واقعی مناسب نیست. برای دیپلوی واقعی از `gunicorn` (لینوکس) یا
  `waitress` (ویندوز) استفاده کن — بالا توضیح داده شده.
- **بدون CSRF و بدون محدودیت نرخ درخواست (rate limit):** برای یک پروژه‌ی
  شخصی/آزمایشی مشکلی ندارد، ولی پیش از باز کردن به‌روی عموم بهتر است اضافه شود.
- **پیام خصوصی زنده نیست:** به‌جای وب‌سوکت، هر چند ثانیه یک‌بار از سرور
  می‌پرسد «پیام تازه‌ای هست؟» (polling). برای دو نفر کافی است ولی فوری‌فوری نیست.
- **بدون تغییر فرمت ویدیو/صدا:** فایل همان‌طور که آپلود می‌شود ذخیره می‌گردد؛
  اگر مرورگر بازدیدکننده آن فرمت را پخش نکند، مشکل خواهد داشت (مثلاً فرمت‌های
  غیرمعمول ویدیو). فرمت‌های رایج مثل mp4/webm و mp3/wav/m4a مشکلی ندارند.
- **بدون رمزنگاری سرتاسری پیام‌ها:** پیام‌ها در پایگاه‌داده به‌صورت متن ساده
  ذخیره می‌شوند (نه پابلیک، فقط برای طرفین گفت‌وگو قابل دیدن‌اند، ولی رمزنگاری
  end-to-end ندارند).
- **SQLite:** برای شروع و چند ده/صد کاربر همزمان کافی است؛ برای مقیاس بزرگ‌تر
  باید به PostgreSQL مهاجرت کرد.
- محدودیت حجم فایل: عکس ۸ مگابایت، ویدیو ۸۰ مگابایت، صدا ۳۰ مگابایت.

## ساختار پوشه‌ها

```
backend/
  app.py            سرور Flask و همه‌ی API
  requirements.txt
  nava.db           پایگاه‌داده (خودکار ساخته می‌شود)
  uploads/          فایل‌های آپلودی + دو فایل نمونه
frontend/
  index.html        تمام رابط کاربری (HTML+CSS+JS در یک فایل)
scripts/
  reset_db.py       پاک‌کردن پایگاه‌داده برای شروع دوباره
run.sh / run.bat     اجرای سریع روی مک/لینوکس یا ویندوز
.env.example         نمونه‌ی متغیرهای محیطی
```


## اتصال امن به پرتال آموزشی گلی‌آباد

Nava از ورود یکپارچه‌ی امن (SSO) با پرتال آموزشی پشتیبانی می‌کند. این روش رمز عبور Nava را به پرتال منتقل نمی‌کند؛ پرتال یک توکن HMAC کوتاه‌عمر و یک‌بارمصرف صادر می‌کند و Nava فقط حساب موجود را وارد می‌کند.

برای فعال‌سازی روی Render:
1. در سرویس Nava و سرویس NoteBookGA/پرتال آموزشی، متغیر محیطی `NAVA_EDU_SSO_SECRET` را با **یک مقدار تصادفی یکسان و حداقل ۳۲ نویسه‌ای** تنظیم کنید.
2. در سرویس NoteBookGA متغیر `NAVA_BASE_URL=https://nava-1.onrender.com` و در سرویس Nava متغیر `EDUCATION_BASE_URL=https://notebookga-usg.onrender.com` را تنظیم کنید.
3. پس از انتشار هر دو مخزن، کاربر باید نام کاربری حساب موجود Nava را در بخش «اتصال حساب Nava» در پرتال ثبت کند.
4. اتصال حساب از نشست کاربر واردشده در Nava تأیید می‌شود و به یک درخواست تصادفی کوتاه‌عمر در پرتال متصل است. سپس گزینه «ورود امن به Nava» توکن یک‌بارمصرف با عمر ۶۰ ثانیه صادر می‌کند.

حساب Nava باید از قبل وجود داشته باشد؛ این اتصال حساب جدید نمی‌سازد و رمز عبور را هم دریافت یا ذخیره نمی‌کند. توکن منقضی یا استفاده‌شده دوباره پذیرفته نمی‌شود. مقدار secret را هرگز در مخزن Git یا پیام عمومی قرار ندهید.
